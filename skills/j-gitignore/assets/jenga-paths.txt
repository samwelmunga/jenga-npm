# skills/j-gitignore/assets/jenga-paths.txt
#
# The canonical catalog of Jenga-owned paths a consuming project may end up
# with on disk. Consumed by audit-gitignore.sh, repair-gitignore.sh and
# untrack-jenga-files.sh — all three read this one file, so the path surface
# is defined in exactly one place.
#
# Format: <tier>TAB<path>TAB<description>
# Blank lines and lines starting with '#' are ignored.
#
# Trailing '/' marks a directory entry and is preserved verbatim into
# .gitignore (git treats 'foo/' as directory-only, which is what we want).
#
# ─── Tiers ───────────────────────────────────────────────────────────────────
#
#   scaffold  Entirely Jenga-owned. Regenerated wholesale by `npm postinstall`
#             or `/distribute`, so nothing of yours is ever lost by ignoring
#             them. Safe default.
#
#   hybrid    A Jenga-managed block inside a file that ALSO holds your own
#             content. lib/generate-agent-context.js and
#             lib/generate-copilot-instructions.js both replace only their
#             managed block and preserve everything outside it. Ignoring these
#             therefore also hides YOUR prose from the repo. Opt-in, never
#             applied without the user saying so.
#
#   board     The project/ working tree (scrum board, todo.md, queue/,
#             rapports/, logs/). Governed by jenga.config.json's
#             `project_files_visibility`. Teams that share a board want this
#             tracked; solo users usually do not. Opt-in.
#
#   optional  Defensive entries for paths no current Jenga version generates.
#             Costs nothing to ignore, guards against a future or third-party
#             agent surface appearing. Opt-in.
#
# ─────────────────────────────────────────────────────────────────────────────

scaffold	.claude/	Claude Code skill/agent mirror — rewritten by every postinstall and /distribute run (scripts/postinstall.js targetRoots). Contains .jenga-postinstall-manifest.json.
scaffold	.agents/	Copilot/Codex skill/agent mirror — the second of postinstall.js's two targetRoots. Contains .jenga-postinstall-manifest.json.
scaffold	.jenga/	`jenga` CLI state directory. lib/commands/init.js already appends this entry itself; listed here so the audit reports it consistently.
scaffold	.jenga-version	Installed-version stamp written at consumer root by scripts/postinstall.js.
scaffold	jenga.config.json	Jenga project config (project_files_visibility, scaffold_visibility). SEE THE WARNING IN SKILL.md — ignoring this means a fresh clone loses your visibility settings.
scaffold	.github/hooks/jenga.json	Copilot CLI hook wiring. "Entirely Jenga-owned output" per scripts/postinstall.js — no user content, unlike copilot-instructions.md.
scaffold	J-CLAUDE.md	Collision-case copy written only when you already had your own CLAUDE.md. A J- file can only ever have been created by Jenga.
scaffold	J-AGENTS.md	Collision-case copy written only when you already had your own AGENTS.md. Jenga-created by definition.
hybrid	CLAUDE.md	Jenga writes a managed block here and preserves content outside it. May contain your own instructions.
hybrid	AGENTS.md	Same managed-block treatment as CLAUDE.md, for Codex and generic AGENTS.md consumers.
hybrid	.github/copilot-instructions.md	Managed-block bootstrap. postinstall.js explicitly notes this one is NOT entirely Jenga-owned.
board	project/	The whole Jenga working tree. Mirrors what apply-project-visibility.sh's JENGA_WORKING_PATHS appends at init time.
optional	.copilot/	Not generated by any current Jenga version (grepped across lib/, scripts/, skills/). Defensive only.
