Feasibility: cheap — sigil/branch detection is prose logic inside SKILL.md; /jenga already resolves natively by directory name on Claude Code, no harness support needed. Note `skills/route/SKILL.md` already implements NL->single-skill matching with board+doc enrichment and should be absorbed rather than duplicated; the genuinely NEW capability is chained multi-skill playbooks, which /route cannot do. Catalog should be generated (lib/generate-skill-allow-list.js already emits the inventory) to avoid drift. Affected scope: skills/jenga/, skills/route/, lib/generate-skill-allow-list.js, mcp/router/. npm test silently writes the committed security-relevant lib/skill-allow-list.json — scripts/postinstall.js:173 passes path.join(packageRoot, "lib", "skill-allow-list.json") as generateSkillAllowList's output target (packageRoot, not consumerRoot — deliberate, since lib/ is never duplicated into a consumer). tests/init.bats:47 invokes `node "$REPO_ROOT/scripts/postinstall.js"`, so under test packageRoot IS the repo and the suite writes into the tracked artifact. Significance: E50_S02_T01's escalation rapport already named "a postinstall.js run" as a corruption vector for the anti-masquerading allow-list; this is that vector reachable from the ordinary test suite, with no check catching it — the E50_S07_T01 lib/ separator bug surfaced only because a human noticed the tree go dirty. Has now cost investigation time three separate times (E50_S02_T02 tester, E50_S07_T01 tester at session start, E50_S07_T01 developer). CORRECTED APPROACH (tester amendment e70461f, supersedes the first-listed fix): do NOT redirect the regeneration to a temp path under test — that removes the noise AND the only signal that has ever caught this bug class; E50_S07_T01's lib/ normalizer regression would have stayed hidden until a real /self-sync, postinstall, or /mirror-public run corrupted the artifact for production. A dirty-tree guard alone is also not implementable as-is, because generateSkillAllowList stamps generated_at: new Date().toISOString() into the artifact and would fire on every run. Correct sequence: (1) make the artifact deterministic — the generated_at timestamp is the SOLE nondeterminism, the skills array is already sorted and deduped and is byte-identical across runs; (2) then add a guard asserting the artifact is unchanged after `npm test`, which at that point fires only on a genuine identifier change. This converts a symptom a human happened to notice into a mechanical gate. Likely epic home E50 (allow-list integrity) as a new story; pre-existing and explicitly out of scope for E50_S07.
