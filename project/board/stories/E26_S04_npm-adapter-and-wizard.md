# Story: npm adapter and setup wizard

As a developer running `/publish setup --type npm`, I want a guided wizard that collects npm-specific configuration and a well-defined adapter contract so that the framework knows exactly how to publish an npm package for this target.

## Acceptance Criteria
- [ ] `skills/publish/adapters/npm.md` exists and defines the npm adapter contract: expected environment variables, input config fields, output artefacts, and success/failure conditions
- [ ] `skills/publish/wizards/npm.md` exists and prompts the user for: package name, access level (public/restricted), dist-tag (default: `latest`), optional custom registry URL, and dry-run preference
- [ ] The wizard writes a valid npm target block to `publish.json` (or creates the file if it does not exist), conforming to the updated schema from S03
- [ ] The wizard surfaces the `NPM_TOKEN` prerequisite: it tells the user what environment variable to set and where to obtain a token from npmjs.com, and it writes an `_INSTRUCTIONS.md` file at `project/instructions/E26_S04_T02_INSTRUCTIONS.md`
- [ ] Running `/publish setup --type npm` on a project that already has an npm target asks the user whether to overwrite or update the existing config
- [ ] The adapter and wizard follow the same structure and conventions as their `mobile-ios` counterparts

## Prerequisites
- An npmjs.com account and an `NPM_TOKEN` (automation token) must be available. The wizard surfaces these requirements and generates an `_INSTRUCTIONS.md` file.

## Definition of Done
- [ ] `skills/publish/adapters/npm.md` exists with contract definition
- [ ] `skills/publish/wizards/npm.md` exists with all prompts defined
- [ ] Both files follow the same structure as `adapters/mobile-ios.md` and `wizards/mobile-ios.md`
- [ ] Wizard output produces a `publish.json` that passes schema validation from S03
- [ ] `project/instructions/E26_S04_T02_INSTRUCTIONS.md` is generated by the wizard and includes NPM_TOKEN setup steps
