## What Was Implemented

A new wizard definition at `skills/publish/wizards/npm.md`. The wizard mirrors the structure of `wizards/mobile-ios.md` (one `## Question:` section per prompt, each with a `Maps to:` line and an `## Expected format:` block) and collects the five inputs required by the S04 story:

1. `package_name` — pre-filled from `package.json` `name` when present
2. `access` — `public` (default) or `restricted`
3. `dist_tag` — `latest` (default) or a custom tag such as `beta`
4. `registry` — `https://registry.npmjs.org` by default; customisable (e.g. `https://npm.pkg.github.com` for GitHub Packages)
5. `dry_run` — yes/no for the first deploy

The wizard also documents the `NPM_TOKEN` prerequisite (what it is, how to generate an Automation token on npmjs.com, and where to set it locally / in CI / for GitHub Packages) and includes the verbatim template that the runtime agent must emit to `project/instructions/E26_S04_T02_INSTRUCTIONS.md`.

A "Post-collection actions" section at the end of the wizard gives the runtime agent the full write sequence: load-or-scaffold `publish.json`, ask overwrite/update when an npm target already exists, emit the target block in the exact S03 schema shape, validate against the schema before saving, then write the instructions file and report to the user.

## Edge Cases & Known Concerns

- **Dry-run has no schema field.** `npmSettings` in the S03 schema has `additionalProperties: false` and does not define a `dry_run` field. Capturing the dry-run preference on the target itself would fail schema validation. The wizard instead captures it into the target-level `notes` string when the user opts in, and omits it entirely when they opt out. If a future story adds a first-class `dry_run` field to the schema, this wizard's `dry_run` section should be updated to write into that field directly.
- **Structural extension beyond `mobile-ios.md`.** The ios wizard is a pure prompt catalogue with no "actions" tail. This wizard adds a "Prerequisite: NPM_TOKEN" section and a "Post-collection actions" section because both are load-bearing for the AC (overwrite prompt, instructions file). This is a deliberate deviation, not a formatting drift.
- **`.claude/skills/` copy not created.** The task text pointed at `.claude/skills/publish/wizards/npm.md`, but that path is a downstream mirror maintained by the distribution mechanism. The source of truth is `skills/publish/wizards/npm.md` (matching where `mobile-ios.md` lives in the source tree). The tester should verify from the source location; the downstream copies will be regenerated by whatever propagation step runs next.
- **T01 not yet implemented.** The sibling adapter task (E26_S04_T01 — `skills/publish/adapters/npm.md`) has not landed. The wizard references the adapter contract but does not depend on it existing yet; the wizard's `secrets` block matches the `npmSecretMap` in the S03 schema regardless.
